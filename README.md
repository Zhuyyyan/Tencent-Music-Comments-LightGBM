# QQ音乐评论数据分析与潜在共鸣评论识别

本项目是上海财经大学《数据科学导论》课程期末项目，围绕QQ音乐榜单歌曲与用户评论，完成数据采集、数据清洗、探索性分析、文本特征工程、机器学习建模以及Gradio交互展示。

## 项目背景

音乐评论既包含用户对歌曲的评价，也承载回忆、情绪表达和粉丝群体互动。本项目尝试分析评论文本、评论长度、歌曲类型、MV标识和粉丝相关词等特征，与评论获赞情况之间的关系，并利用机器学习模型筛选具有大众情感共鸣特征的潜在获赞评论。

需要说明的是，当前训练标签定义为：

```python
liked_count > 0
```

即获得至少一次点赞的评论记为正类，零点赞评论记为负类。因此，本项目实际研究的是评论的获赞倾向和文本共鸣特征，而不是对平台高赞热评排名的严格预测。

## 数据采集

项目通过 `qq_music.py` 获取QQ音乐多个榜单中的歌曲信息，并抓取歌曲评论。当前数据包括：

- 510首去重歌曲；
- 50,271条去重评论；
- 歌曲名称、歌手、榜单类型、MV标识等歌曲字段；
- 评论内容、点赞数、评论时间等评论字段。

评论样本由两部分组成：

- 接口返回的精彩热评；
- 多页最新评论。

最新评论发布时间较近，点赞尚未充分积累；精彩热评则已经经过平台曝光和用户互动。因此，点赞数还会受到评论来源、发布时间、曝光位置、歌手热度及粉丝群体等因素影响。这是当前数据集的重要限制。

## 数据分析与特征工程

项目主要完成了以下处理：

1. 检查缺失值、重复值和异常时间；
2. 使用IQR方法观察点赞数的长尾分布；
3. 对评论文本进行 `jieba` 分词和停用词过滤；
4. 使用TF-IDF提取500维文本特征；
5. 构造评论长度、MV标识、歌曲类型编码和粉丝词命中数等基础特征；
6. 使用SMOTE缓解训练集类别不平衡。

IQR盖帽后的点赞数仅用于描述性分析和可视化，不作为分类标签。模型分类标签仍由原始 `liked_count > 0` 生成。

## 机器学习模型

项目比较了以下五种分类模型：

- 逻辑回归；
- 决策树；
- 朴素贝叶斯；
- 随机森林；
- LightGBM。

数据按照8:2划分训练集和测试集，并在训练集上使用SMOTE。当前实验中，LightGBM取得相对较好的综合表现：

| 指标 | 结果 |
|---|---:|
| Accuracy | 60.72% |
| F1-Score | 54.69% |
| ROC-AUC | 0.656 |

这些结果说明文本和基础属性具有一定的区分信息，但模型能力仍然有限，不能将输出解释为评论成为真实热评的确定概率。

## Gradio展示系统

`app.py` 使用已保存的以下组件进行在线推理：

- `best_model.pkl`
- `tfidf_vec.pkl`
- `trained_features.pkl`

前端首先计算LightGBM原始输出，再根据少量情绪词和低共鸣词进行规则调整。最终展示值称为“潜在共鸣得分”，而不是经过统计校准的概率。

规则层主要用于课程演示和典型案例分析，具有较强的人工设定性质。例如，明星粉丝效应、歌曲背景和具体事件语境仍难以依靠少量关键词准确识别。

## 主要不足与改进方向

1. 当前数据没有保存评论来自精彩热评还是最新评论，后续采集应增加 `comment_source` 字段，并记录采集时间。
2. `liked_count > 0` 更接近“是否获赞”标签，后续可尝试歌曲内部点赞分位数或平台热评标识。
3. 模型缺少歌手热度、评论曝光位置、发布时间和早期互动等上下文信息。
4. 后续可按歌曲分组划分训练集与测试集，减少同一歌曲信息同时进入两部分数据的影响。
5. 前端规则只适合辅助展示，不应代替模型验证或被解释为真实平台推荐机制。

## 项目定位

本项目完整实现了从网络数据采集、数据分析、自然语言处理、机器学习训练到云端交互展示的课程实践流程。其适用定位是：

> 基于QQ音乐评论数据，分析获赞评论的文本特征，并筛选具有大众情感共鸣特征的潜在评论。

## 🗄️ 数据库存储补充 (Database Storage)

为对应课程项目中“数据存储”部分，仓库额外补充了 `database/` 文件夹，用于将项目 CSV 数据导入 SQLite 数据库，便于后续 SQL 查询和复现检查。

```text
 database/
 ┣ 📜 create_tables.sql                 # 数据表结构文件：包含 songs 与 comments 两张表的建表语句
 ┣ 📜 database_storage.py               # 数据库存储脚本：读取 CSV 并写入 SQLite 数据库
 ┗ 📄 README_database.md                # 数据库存储说明：记录字段含义、运行方式与复现步骤
```

运行方式：

```bash
python database/database_storage.py
```

运行后会在项目根目录生成：

```text
qqmusic_comments.db
```

其中包含两张数据表：

- `songs`：存储歌曲 ID、歌曲名称、歌手名称、歌曲类型、MV 标识和来源榜单等信息；
- `comments`：存储歌曲 ID、评论 ID、用户昵称、评论内容、点赞数和评论时间等信息。

该部分不改变原有分析流程，只作为数据库存储与 SQL 文件的补充材料。
